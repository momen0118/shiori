# 旅のしおり JSON形式

旅のしおりツールに読み込める・書き出されるデータの形式です。
Claudeのプロジェクトのナレッジとリポジトリの両方に置いて使います。

- Claudeと旅行の相談をした結果を、この形式で出してもらってしおりに読み込む
- しおりから書き出したものをClaudeに貼って、組み直してもらう
- しおりのバックアップと、夫に送るリンクの中身も同じ形式

---

## プロジェクトの指示に貼る文

````
旅行の計画を一緒に考える相談相手をしてください。
しおりに読み込みたいと言われたら、ナレッジの FORMAT.md の形式で JSON を1つだけ、json のコードブロックで出してください。
地図URL・サイトURL・予約番号・予約名義は、私が渡したもの以外は絶対に入れないでください（わからなければ項目ごと省略）。
しおりのJSONを貼って組み直しを頼んだときは、変えていない部分もそのまま残した JSON 全体を返してください。
````

---

## Claudeが守ること

1. 出力は json のコードブロック1つだけ。前後に説明を書くのはいいが、JSONは1つにまとめる。
2. **地図URL・サイトURL・予約番号・予約名義は、ユーザーが渡したものだけを使う。** それらしいURLや番号を作らない。不明なら項目ごと省略する。
3. 必須なのは「名前」系だけ（しおりの `title`、立ち寄りの `name`、いけたらいくの `name`）。それ以外はわからなければ省略してよい。空文字より省略を優先。
4. 日付は `YYYY-MM-DD`、時刻は `HH:MM`（24時間、ゼロ埋め）。
5. 移動の所要時間は書かない（しおりが前後の時刻から計算する）。
6. 組み直しを頼まれたときは、受け取ったJSONの**全体**を返す（しおりの側で「置き換え」として読み込むため）。触っていない日や項目もそのまま残す。
7. 「寄れそうな所ある？」のように、いけたらいくだけを出すときは、`wishlist` だけを入れた最小の形でよい（下の「いけたらいくだけの形」参照）。
8. ラベルはなるべく決まった候補から選ぶ。合うものがなければ6文字以内で自由に書いてよい。

---

## 全体の形

```json
{
  "format": "tabi-shiori",
  "version": 1,
  "title": "しおりのタイトル",
  "startDate": "2026-12-05",
  "endDate": "2026-12-06",
  "done": false,
  "cover": {
    "pattern": "gingham",
    "color": "wakakusa",
    "destination": "行き先",
    "note": "ひとこと"
  },
  "packing": ["持ち物1", "持ち物2"],
  "days": [
    {
      "date": "2026-12-05",
      "items": [
        { "type": "stop", "name": "立ち寄り先" },
        { "type": "move", "mode": "車" },
        { "type": "stop", "name": "次の立ち寄り先" }
      ]
    }
  ],
  "wishlist": [
    { "name": "いけたらいく所" }
  ],
  "memo": "しおり全体のメモ"
}
```

---

## 項目の説明

### しおり

| 項目 | 必須 | 内容 |
|---|---|---|
| `format` | ○ | 常に `"tabi-shiori"` |
| `version` | ○ | 常に `1` |
| `title` | ○ | しおりのタイトル |
| `startDate` / `endDate` | | 旅行の初日・最終日 |
| `done` | | 済み（思い出の棚に入れる）なら `true`。省略時は `false` |
| `cover` | | 表紙（下記） |
| `packing` | | 持ち物。文字列の配列、1要素＝1項目。分類はしない |
| `days` | | 日ごとの行程（下記）。配列の順番＝1日目、2日目… |
| `wishlist` | | いけたらいく（下記） |
| `memo` | | しおり全体の自由メモ。URLと電話番号はしおりの側でタップできるようになる |

### 表紙 `cover`

| 項目 | 内容 |
|---|---|
| `pattern` | 柄。`check`（チェック）/ `gingham`（ギンガム）/ `stripe`（ストライプ）/ `border`（ボーダー）/ `dot`（水玉）/ `grid`（方眼）/ `wave`（波線）/ `diagonal`（斜線） |
| `color` | 色。`kaki`（柿）/ `yamabuki`（山吹）/ `wakakusa`（若草）/ `seiji`（青磁）/ `ai`（藍）/ `fuji`（藤）/ `sakura`（桜）/ `nezumi`（鼠） |
| `destination` | 行き先（表示用の文字） |
| `note` | ひとこと |

柄と色は、ユーザーが指定しなければ省略してよい（しおりの側で決める）。

### 日 `days[]`

| 項目 | 内容 |
|---|---|
| `date` | その日の日付。省略時は `startDate` から順番に数える |
| `items` | 立ち寄りと移動を**行程順に**並べた配列 |

`items` には `stop`（立ち寄り）と `move`（移動）が入る。基本は「立ち寄り → 移動 → 立ち寄り …」の交互だが、移動がわからなければ立ち寄りを続けて並べてよい。

### 立ち寄り `{"type": "stop"}`

| 項目 | 必須 | 内容 |
|---|---|---|
| `type` | ○ | `"stop"` |
| `name` | ○ | 名前（施設名・場所名） |
| `label` | | ラベル。候補：`観光` `あそぶ` `食事` `カフェ` `買い物` `休憩` `泊まる` `温泉`。合わなければ6文字以内で自由に |
| `start` | | 開始時刻 `HH:MM` |
| `end` | | 終了時刻 `HH:MM`。宿のチェックインのように終わりがなければ省略 |
| `memo` | | メモ。URLや電話番号を書いてもよい |
| `siteUrl` | | お店などのサイト。**ユーザーが渡したものだけ** |
| `mapUrl` | | Googleマップの共有リンク。**ユーザーが渡したものだけ** |
| `reservation` | | 予約（下記）。予約がなければ省略 |

`siteUrl` はあとから足した項目。`version` は 1 のまま（足しただけなので、前のデータはそのまま読める）。

### 移動 `{"type": "move"}`

| 項目 | 内容 |
|---|---|
| `type` | `"move"` |
| `mode` | 手段。`車` / `徒歩` / `電車` / `バス` など。省略時は `車` |
| `memo` | 道のメモ（例：`国道〇号経由`） |

所要時間は書かない。

### 予約 `reservation`

施設名と日時は、つながっている立ち寄りの `name` と `start` を使うので書かない。

| 項目 | 内容 |
|---|---|
| `number` | 予約番号。**ユーザーが渡したものだけ** |
| `holder` | 予約名義。**ユーザーが渡したものだけ** |
| `checkIn` / `checkOut` | チェックイン・チェックアウト時刻。ラベルが `泊まる` の立ち寄りで使う |
| `meetTime` | 受付・集合時刻。`泊まる` 以外の立ち寄りで使う |
| `memo` | メモ。電話でしか予約できない店の番号など |

メールへのリンクは、しおりの側で予約番号からGmailの検索リンクを作るので書かない。

### いけたらいく `wishlist[]`

| 項目 | 必須 | 内容 |
|---|---|---|
| `name` | ○ | 名前 |
| `siteUrl` | | お店などのサイト。**ユーザーが渡したものだけ** |
| `mapUrl` | | Googleマップの共有リンク。**ユーザーが渡したものだけ** |

## 例：1泊2日

```json
{
  "format": "tabi-shiori",
  "version": 1,
  "title": "〇〇温泉 1泊2日",
  "startDate": "2026-12-05",
  "endDate": "2026-12-06",
  "cover": { "pattern": "gingham", "color": "seiji", "destination": "〇〇温泉" },
  "packing": ["歯ブラシ", "充電器", "タオル", "着替え"],
  "days": [
    {
      "date": "2026-12-05",
      "items": [
        { "type": "stop", "label": "あそぶ", "name": "〇〇公園", "start": "10:00", "end": "11:00", "memo": "駐車場は北口側" },
        { "type": "move", "mode": "車", "memo": "〇〇道経由" },
        { "type": "stop", "label": "食事", "name": "〇〇食堂", "start": "12:00", "end": "13:00" },
        { "type": "move", "mode": "車" },
        {
          "type": "stop", "label": "泊まる", "name": "〇〇旅館", "start": "15:00",
          "reservation": { "number": "AB12345", "holder": "〇〇", "checkIn": "15:00", "checkOut": "10:00" }
        }
      ]
    },
    {
      "date": "2026-12-06",
      "items": [
        { "type": "stop", "label": "買い物", "name": "道の駅〇〇", "start": "10:30", "end": "11:30" }
      ]
    }
  ],
  "wishlist": [
    { "name": "〇〇ベーカリー" }
  ]
}
```

## 例：いけたらいくだけの形

しおりの側で「いけたらいくだけ足す」を選んで読み込む。`wishlist` 以外は無視される。

```json
{
  "format": "tabi-shiori",
  "version": 1,
  "wishlist": [
    { "name": "〇〇美術館" },
    { "name": "〇〇の滝" }
  ]
}
```

## しおりの側の読み込みルール（実装メモ）

- 読み込みは3種類：**新しいしおりとして** / **今のしおりと置き換え**（置き換え前の状態を1つ控えて、戻せるようにする）/ **いけたらいくだけ足す**
- 読み込む前に中身の確認を出す（例：2日間・立ち寄り6件・予約1件・いけたらいく1件）
- 知らない項目は無視する。必須項目（`title` / `name`）が欠けていたら、どこが足りないかを平易な言葉で出して止める
- コードブロックの記号ごと貼られても読めるように、最初の `{` から最後の `}` までを取り出して読む
- ラベルが7文字以上なら6文字で切る
- `done` は読み込み時に引き継ぐ（置き換え時は今のしおりの値を優先してよい）

## バックアップの形（しおりの側だけで使う）

本棚のメニューの「全部まとめてバックアップ」で書き出される形。Claude に渡すものではない。
`shiori` の中身は上の「しおり」の形そのまま。`id` は端末の中でしおりを見分けるための番号で、戻すときに「同じしおり」かどうかを判断するのに使う。

```json
{
  "format": "tabi-shiori-backup",
  "version": 1,
  "exportedAt": "2026-11-19T09:00:00.000Z",
  "books": [
    { "id": "8f0c…", "updatedAt": "2026-11-19T08:55:00.000Z", "shiori": { "format": "tabi-shiori", "version": 1, "title": "…" } }
  ]
}
```

戻すときのルール：

- 端末にない `id` のしおりは、新しく入れる
- 同じ `id` で中身が同じしおりは、何もしない
- 同じ `id` で中身が違うしおりは上書きする。上書き前の状態はそのしおりの控え（「置き換える前に戻す」）に入れるので、戻せる
- 端末にあってバックアップにないしおりは、そのまま残す（消さない）

## 夫に送るリンクの形

`https://（サイトの場所）/#s=（データ）`

- データ＝しおりの JSON（上の「しおり」の形、改行なし）を lz-string の `compressToUint8Array` で圧縮し、URL 用の base64（`A-Z a-z 0-9 - _`、末尾の `=` なし）にしたもの
- `#` から後ろはサーバーに送られないので、どこにも保存されない
- 受け取った側は、読み込みと同じ点検をしてから「見るだけ」で開く。何も保存しない
